# dsh-skill-installer

DSH 技能安装器：在设置页里**看**已有技能、**装**新技能、**导入**技能包、**管**（启用/停用/删除）技能。

- 面板位置：**设置 → 技能安装器**（设置左侧导航里的独立一项，与「思考强度」「提示缓存」同层）
- 模型工具：`skill_install`（`op=list / install / import / toggle / uninstall / roots`）

## 装什么

技能必须是下面两种形状之一（与 DSH 自身的技能发现规则一致）：

```
技能包/
  some-skill/
    SKILL.md          # frontmatter 必须有 name 与 description
    任意资源文件…
```

或根目录直接放单文件 `some-skill.md`。技能名用 kebab-case（小写字母、数字、连字符）。

## 装到哪

面板顶部**只有一个「安装到」下拉**，它同时决定「装到哪」和「列哪个工作区」：

| 选项 | 路径 | 生效范围 |
| --- | --- | --- |
| 用户级（全局） | `~/.dsh/skills` | 所有会话可见 |
| 工作区：<名称> | `<工作区>/.dsh/skills` | 只对该项目生效 |

下拉下面实时显示**解析出来的真实目录**，点安装之前就能确认装到哪。

> 早先这里是两个互不相干的下拉（顶部「工作区」+ 装技能区「目标根」），结果是
> 「顶部选了工作区、装技能区还停在用户级」——装到哪全看后一个下拉。语义重叠的
> 下拉必须合成一个。另外 `~/.dsh/skills` 与 `<主目录>/.dsh/skills` 是同一个目录，
> 工作区退化成主目录时「工作区级安装」会静默变成「用户级安装」，所以那种情况直接报错。

另外两个 `.agents/skills` 根只读显示，不会被本插件写入。

## 技能列表

技能按**技能根分组**，每组标题写明属于哪个工作区，并显示该根的真实路径。
同名技能在多个根里并存时**全部列出**（不隐藏被遮蔽的副本，否则那个工作区的副本
既看不见也删不掉），被遮蔽的标注「被 <根名> 遮蔽」。

启用 / 停用 / 删除都带技能所在根的路径，宿主半按路径精确定位——多个工作区下有
同名技能时，只靠名字会操作到别的根。

## 导入

面板「导入」区两条路：

- **选文件** —— 浏览器出于安全拿不到文件真实路径，所以由浏览器读字节、base64 传给宿主，宿主落临时文件后解包导入；
- **填绝对路径** —— 如 `/sdcard/Download/xxx.zip`，要求该路径在宿主上真实存在。

支持 `.md` 单文件、技能目录、`.zip`、`.tar`、`.tar.gz`。归档解到临时目录、装完即删；
归档里多包一层同名目录会自动剥掉。

## 技能管理

可写根里的每个技能有三个动作：

- **停用 / 启用** —— 改 `SKILL.md` 的 frontmatter（`disable-model-invocation: true` 与 `user-invocable: false`），
  **不搬文件、正文一字不动**，随时能开回来；
- **修复** —— 只在该技能 frontmatter 结束符损坏时出现（见下）；
- **删除** —— 默认先备份到目标根的 `.backup/` 再删。

只读根（`.agents/skills`）的技能不给按钮，明确标注「只读根，不能改」。

### frontmatter 分隔符必须精确是 `---`

DSH 要求 frontmatter 的起始行与结束行**整行精确等于 `---`**，`----` 这类都不认，
遇到就**静默忽略整个技能**（只在日志里 warn 一句）。

本插件 v0.2.x 的「启用/停用」有个 bug：切片差一个字符，每切换一次就给结束符多加
一根横线，切几次后 `---` 变成 `-------`，技能就此读不到。v0.3.1 修好了，并且：

- 切换时一律把结束符重写成标准 `---`，**顺带把老版本写坏的文件修回来**；
- 损坏的文件在列表里显眼标出「DSH 读不到它，启用也没用」，并给一个「修复」按钮；
- 自带的解析器改成与 DSH **逐字一致**的严格判定，不再「我这边认、DSH 那边不认」。

往返切换是字节级幂等的：连切两次，文件与原始完全相同。

## 工作区级技能只对那个工作区生效

DSH 按**会话的工作目录**找技能根。装在 A 工作区的技能，在 B 工作区的会话里读不到——
这不是 bug，是工作区级的作用域。要处处可用就装到用户级。

## 三种来源

| 来源 | `ref` 写法 | 实际动作 |
| --- | --- | --- |
| `local` | 本地绝对路径 | 直接复制 |
| `npm` | 包名，如 `some-skills-deck` | `npm pack` → `tar -xzf` |
| `github` | `owner/repo` 或完整 URL | `git clone --depth 1` |

技能包里的技能放在 `bundled-skills/` 或 `skills/` 子目录时会被自动认出来；没有这两个子目录就用包根。

同名技能默认**不覆盖**；勾选「同名覆盖」后会先把旧的挪到目标根的 `.backup/` 下再装。
卸载默认也留备份，`skill_install{op:'uninstall', overwrite:true}` 才不留。

## 安装本插件

```bash
dsh plugin --profile web add github:liancha22/dsh-skill-installer
```

装完**重启该 profile**（`patchReload: startup`），然后刷新浏览器页面。

卸载：`dsh plugin --profile web remove dsh-skill-installer`，再重启。

## 验收判据

1. **设置 → 技能安装器**（设置左侧导航里的独立一项）出现该页；
2. 顶部「安装到」下拉能列出 DSH 自己的工作区，选中后下面显示该工作区的真实目录；
3. **选「工作区：X」后装技能，`<X>/.dsh/skills/<name>/SKILL.md` 真的存在**（不是装到 `~/.dsh/skills`）；
4. 技能列表按根分组，工作区技能的标签写明是哪个工作区，并显示该根路径；
5. 停用后卡片标「已停用」，`SKILL.md` 里出现 `disable-model-invocation: true`；启用后该字段消失、正文未变；
6. 导入一个 `.zip` 能装进技能（导入同样遵循顶部选的目标）；
7. 删除后目录消失，`.backup/` 里留有副本（未勾选不留备份时除外）；
8. 两个工作区里各有同名技能时，删其中一个只影响那一个。

## 已知边界

- 技能文件本身改动会被 DSH 的文件监听自动拾取；**宿主半**（本插件的 JS）改动需要重启 profile。
- 装 npm/GitHub 来源需要宿主能跑 `npm` / `git` / `tar`，命令超时 120s；归档解包需要 `unzip` / `tar`。
- 单个技能包超过 200 个文件会被拒绝（防呆，正常技能包远小于此）。
- frontmatter 解析只认 `key: value` 与布尔；技能头部够用，复杂 YAML 不支持。
- 面板的实际渲染效果尚未在真机肉眼验收（本机无障碍服务未开启，无法点按确认）。
